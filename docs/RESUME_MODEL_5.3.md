# 5.3.0 简历版本模型、编辑与隔离

## 模型与迁移

沿用原有 IndexedDB、current工作区、按稳定ID拆行的versions集合、统一防抖保存与完整备份；不新增数据库或第二套自动保存系统。旧版版本对象保留原有排版、勾选、摘要、文件名和目标院校等字段，增加 `resume53.schemaVersion=1`。

`initializeResumeVersions53(state)` 在首次打开5.3时，为尚未扩展的版本建立元数据回退、迁移旧的显示选择与目录状态，并返回是否有新增数据。旧版本特定目标院校迁入profile.targetSchool的独立覆盖；已有四类经历的简历表述和显式includedFields优先级继续进入最终内容，不修改已初始化5.3版本的覆盖。迁移和只打开查看不更新修改时间；旧数据没有真实版本级时间时显示“尚无修改时间”，不伪造最近修改。

| 新字段 | 作用 |
| --- | --- |
| base | 个人资料、经历等底稿文本与稳定引用的回退；排除原图/Base64、本机Blob指针和素材正文 |
| overrides | 字段路径到独立正文，使用是否存在键判断；空字符串也是有效覆盖 |
| labels / styles | 模块与字段标题、字号和颜色等局部显示覆盖 |
| hidden | 模块、条目和字段独立隐藏，不等于删除底稿 |
| sectionOrder / recordOrder / fieldOrder | 模块、条目、字段的顺序 |
| addedRecords / addedFields / customModules | 当前版本独有条目、字段和结构化模块，默认不进入底稿 |
| cover / toc | 封面标题与启用状态；目录有独立章节选择，不因字段勾选生成字段目录 |
| template / design | 模板、分栏、字体及按模板保留的设计参数，原有排版字段继续兼容 |
| targets53 / createdAt53 / modifiedAt53 | 多个自由文本院校、创建及实际修改时间 |

标准路径沿用旧的字段身份：`profile.name`、`awards:<稳定ID>:reflection`、`exams:<考试ID>:subjects:<科目ID>:score`。版本专属字段使用自身稳定ID，不依赖数组下标。

## 解析与数据隔离

`resolveResume53(id)` 纯解析并返回 `{workspace, version, modules}`。未覆盖的普通版本字段继承当前底稿；已有覆盖保留当前版本正文。底稿删除条目时，以回退元数据继续显示，并带 `sourceMissing` 提示。解析投影不会写入全局底稿、其他版本或资产正文。

`preserveResumeReferences53(state)` 在确认删除底稿记录之前，将最新底稿文本合入普通版本的回退，保留已删除的旧引用；不更新版本修改时钟、不覆盖独立字段、不改变空白版本。它与真正删除操作一同经过原工作区保存事务。因此底稿先修改再删除，也不会退回最初创建时的旧文本。

普通版本和空白版本的区别：空白版本初始字段是空白快照，不自动跟随所有底稿内容；在其中明确恢复字段时复制当前底稿值。普通版本默认的继承字段会跟随底稿。该差异避免“空白新建”立即重新填满资料。

素材仍只保留在原素材库。版本的照片只含assetId与裁剪等元数据，不复制原图。全局删除仍被已完成简历引用的原件时应提示先解除引用；删除某个简历版本不会删除全局素材或已经生成的外部文档。外部备份校验会拒绝版本内复制的原始附件数据、本机指针及失效引用。

## 编辑与保存

管理中心完整展示所有版本，最近修改卡片仅为快捷入口，不新建重复记录。新建支持从底稿或空白；复制采用新版本ID；删除连续两次确认。管理中心最近修改排序只使用真实修改时间。

编辑器完整内容模式采用模块/条目/字段三级选择、结构化条目与字段、自定义模块、正文与名称、局部字号/颜色。普通状态没有拖动手柄，明确进入排序模式后提供Pointer Events手柄及触控可用的上/下移；其他排序也提供按钮，不依赖悬停。恢复操作必须确认范围，保留隐藏、顺序和排版。内容/设计切换使用同一个版本，不初始化新版本。

`changeResumeVersion53` 先比较真实编辑数据；有变化才更新时间并产生会话撤销步骤。连续同字段输入在650ms窗口合并，历史最多40步，不持久化为无限数据库历史；大回退base不重复放入撤销快照。`undoResume53` 和重做在保存后仍可执行，结果通过原自动保存写回。输入框中快捷键保留浏览器本身的文字撤销，非输入环境支持编辑器Ctrl/Cmd+Z、Shift+Z及Y。

显式保存和自动保存均使用原CAS、严格事务和真实提交状态；状态未提交时不标记成功。保存失败保留本地待保存数据，不静默回退旧状态。不同标签页即便编辑不同版本，也采用工作区级保守冲突拒绝；不自动合并。实际浏览器检查证明先提交的版本保留，过期标签页返回保存失败，其本地另一版本修改仍可导出备份。

## 接口

轻量的 `js/resume-model53.js` 可直接使用：

- `initializeResumeVersions53(state)`：旧版本扩展，返回changed。
- `createResumeVersion53(name, targets, {blank})` / `cloneResumeVersion53(id)`：新建或复制。
- `resolveResume53(id, state)`：纯最终投影，提供标准化模块、条目、字段、来源和隐藏状态。
- `changeResumeVersion53(id, fn, {tag})`：一次可撤销的版本修改，返回是否真变化。
- `undoResume53(id, redo)`：会话撤销/重做。
- `restoreResumeScope53(version, {module, recordId, path})`：范围内正文和名称恢复；调用方负责确认。
- `preserveResumeReferences53(state)`：底稿删除前更新回退，不更新版本时钟。

按需加载的 `js/resume53.js` 负责管理与编辑页面：prepareResume53、resumeManagerPage53、resumeEditorPage53、getResumeReadOnlyPage53、bindResume53。精简模式进入只读审阅；编辑工作区在支持的空间展开，相关复杂界面不在首页初始化。

## 与设计和导出联动

所有模板使用同一解析投影。标题/正文、可见性、排序和版本专属内容都来自最终模块，而非重新读取原始底稿。导出模块在解析后捕获独立快照，再按需读取附件，避免异步生成时更改底稿。原始版本模板只改变有效外观，不删除存储中的模板配色。导出中心保持当前版本，文件名与管理中心版本名称分离。

所有模板的Word均为原生可编辑段落/标题/列表/图片结构；本文的模型测试不等同实际Word软件打开测试，DOCX结构、PDF与其他格式的具体验证以导出专项报告为准。

## 实际测试与边界

`tests/resume53.test.mjs` 8项通过：旧版本迁移幂等、不伪造时钟、多版本隔离、主动清空、继承与已删条目、精确恢复、保存后撤销/重做、自定义结构、空白/复制、备份验证和持久化、删除前保留最新底稿及其他/空白版本保护，以及旧目标院校、四类简历表述和可选优先级的精确迁移。

`tests/resume53-browser.mjs` 使用真实Windows Edge无头浏览器、隔离本机数据库，检查管理中心操作、字段实时徽标和目录标题、版本隔离、保存/刷新、撤销/重做、确认恢复、自定义条目字段、封面目录、模板往返、导出文件名、1024×768触控上移下移、双重删除确认和不同版本跨标签页冲突。结果见docs/evidence53/resume53/summary.json；截图为manager.png和tablet-content.png。对应的平板是视口和触控模拟，不是物理iPad。最终实际浏览器10项通过、页面异常为0；最后一项调用真实底稿删除处理器并确认，证明版本保留删除前最新正文且编辑时钟不变。

已知边界：回退保留文本元数据，多个版本仍会各自占用这些文本；大原图和文件不复制。单个版本的编辑状态随原版本记录增量提交，并非每个字独立一行。撤销会话刷新后不保留，保存的最终编辑状态会保留。跨标签页不自动合并。空白版本采用明确空白快照语义；完整/精简模式使用同一数据库。上述取舍避免再次更换持久层或引入复杂编辑依赖。
