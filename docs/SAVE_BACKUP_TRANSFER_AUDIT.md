# 保存、备份、设备接力调查与待确认方案

> 2026-10-23：用户已确认采用下述方案，本地整合已完成。本文保留为整合前调查；当前实现与验收见 [本地整合报告](LOCAL_INTEGRATION_REPORT.md)。

调查对象：5.0 已发布实现。本轮没有改动 autosave.js、backup.js、transfer.js、storage.js 或 app.js 的保存流程。

## 当前实现

| 功能 | 实际调用与产物 | 用途与边界 |
| --- | --- | --- |
| 自动保存 / 保存进度 | autosave.js 的 save()；写本浏览器 IndexedDB 的 current | 保存录入资料、上传附件、设置等当前工作台数据。500ms 防抖；指纹排除导航，未修改时不重复写。学习、日历、题库等另有独立小记录和写队列。不会生成外部文件。 |
| 备份数据 | save() → getCurrentBackup() → createBackup() | 下载完整个人 JSON，文件名前缀 Qicheng_Backup。覆盖用户资料、文件、设置、倒计时、阅读/日历、答题草稿及成绩、错题收藏、自定义资源及新增题库目录。排除官方可重新获取资源、程序文件、临时页面状态和设备时间元数据。 |
| 生成最新同步文件 / transfer | 同样 save() → getCurrentBackup() | 与备份是同一 backupVersion:1 数据结构，主要差别是 Qicheng_Transfer 文件名、发送/接收引导和操作结果提示，不存在第二套同步算法。 |
| 恢复备份 / 接收 JSON | 同一个 backupInput、parseBackup()、commitBackup() | 同样先校验、预览、确认，再原子替换当前本机全部用户数据，保留接收端官方资源。失败不清空旧资料。接力入口额外把恢复成功后的界面定位回设置并显示本机接收记录。不会合并两台设备的编辑，不是联网同步。 |
| 保存本地文件 / HTML | save() → offlineHTML() | 下载程序、库、字体、全部用户资料及已安装官方/自定义资源的可编辑独立 HTML。打开副本使用独立的数据空间；不自动连接原 PWA 的数据库，也不接收 PWA 更新，不是可安装 PWA。适合长期留档或没有网站时离线编辑，不适合日常多端接力。 |

Android、iOS/iPadOS 和 Windows 使用完全相同的 JSON 结构，仅下载/分享的系统界面与默认目录有差别。Backup 文件与 Transfer 文件可以互相恢复，无须转换。

设备时间保存在 `meta:device`：最后真实用户写入时间、最近成功导入时间、导入文件生成时间。恢复时采用本机成功事务的时间，而不是把来源设备的接收记录复制过来。它不能证明另一台设备已收到文件，也不能检测用户已通过聊天/文件传输完成同步。

## 已发现的界面重叠及保存提示边界

1. 接力与备份的导出、导入入口重复，名字容易令人误以为是两种格式。
2. “保存进度”已经出现在多数页面的顶部，但首页与设置页主动隐藏了它，设置中缺少一个清楚的“立即保存”。
3. 当前 save() 的成功提示主要反映 current 的提交，不等同于一切独立写队列都已成功结束。接力/备份和应用更新会额外等待相关队列；统一手动保存时也应补齐这一点。
4. “保存本地文件”没有直接写明 HTML 和独立副本，容易与“立即保存”或常规 JSON 备份混淆。
5. 用户下载的 JSON 是当时快照，不会自动继续更新。导入是整份替换，先留接收端备份的引导应保留。

## 建议整合（尚未执行）

统一为设置中的“保存与设备接力”：

- **立即保存到本机**：主动提交内容编辑和答题草稿，等待资源、首页、阅读/日历等已接受的必要写入；所有任务成功才提示“已保存”。没变化时不新增 current 写入，保留原防抖与失败提示，不在切页或开菜单时调用保存。
- **导出完整 JSON**：唯一的备份/接力导出按钮。下方说明“既可留作备份，也可发送给另一台设备”。继续使用现有完整备份格式，兼容历史 Backup / Transfer 文件。
- **导入完整 JSON**：唯一导入按钮；校验、信息预览、覆盖确认和失败保护沿用原实现，明确“不自动合并资料”。
- 显示“本机最后保存”“最近导入”“来源文件时间”，将发送/接收分步说明合并为可展开的帮助。
- “高级工具”中保留 **导出可编辑 HTML 副本** 和备份文本，解释 HTML 含程序与资料、是独立副本，不与 PWA 持续同步。若用户确定不需要 HTML，之后再删除入口；本轮未删除。
