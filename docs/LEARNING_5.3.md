# 5.3 学习、复习与题库管理

本模块复用 5.2.1 的 IndexedDB、题目独立行、永久源身份、事务、JSON 预检和增量提交。新增界面位于 `js/learning53.js`，仅进入学习页面、查看笔记或主动全局搜索后加载；首页直接读取一条概要，不加载本模块和完整历史。

## 路由和集成

应用先 `await prepareLearning53(route)`，再 `learningPage53(route)`，渲染后调用 `bindLearning53()`。支持 `learning-review`、`question-bank`、`question:<URL编码源包>/<URL编码题ID>`、`quiz-history`、`learning-stats`。`quiz` 路由只更新保护身份，不预读全部题目、收藏夹和历史。

题目和笔记使用 `(源题包ID, 永久题ID)`；展示学习题库可以合并多个来源。既有 `learningBankId/learningQuestionId` 映射保留，历史仍保存题目快照、用户答案和提交时评分。手动新增通过既有 `ensureManualQuestionPack` 写入所选学习题库的手动来源包，没有新建第二套题库系统。

## 错题和收藏

既有 `quiz:mark:*` 独立记录保留。`wrong` 表示最近一次正式作答是否错误；新增 `reviewPending` 表示待复习，`mastered` 为用户明确掌握状态，`lastWrongAt` 为最近实际错误时间。正确复习更新最近评分，但不会自动替用户标记掌握；再次答错会回到待复习。同一永久身份始终只有一条学习标记。

`learning:folder:<id>` 保存可重命名收藏夹及源身份列表，支持一题放入多个收藏夹。添加/移出收藏夹不改变掌握状态；星标是另一种已有独立收藏标记。统计界面明确标为“星标收藏”，避免把多个收藏夹成员关系当成多道题。

筛选后的复习使用现有答题引擎创建最多 200 题的一组练习。组内只保存草稿，全部答完并提交后统一评分、展示解析；计时、未完成恢复与历史快照均复用。已从题库移除的题不进入新练习，原学习标记与批注继续保留并提示。

## 个人笔记与提前泄露保护

笔记继续使用既有 `question:note:<pack>/<qid>`，通过读取到的 `noteRevision` 做事务 CAS。输入短时防抖，失焦、切页、显式保存和应用备份/更新调用 `flushLearning53()`；状态在真正提交后变为已保存。关闭编辑器不丢弃失败草稿。

`getPendingLearningRecords53()` 可把未成功落盘的笔记投影成正常备份记录；配额失败时外部备份仍能救出这部分内容。恢复或清除成功提交后调用 `resetLearning53()`，事务失败时不提前清理笔记内存。新绑定时回收脱离 DOM 的宿主，近期缓存以 30 份为目标淘汰没有未保存输入和活动宿主的旧条目；脏草稿保留到提交或备份。

### 快速输入与异步重绑竞态回归

实际单文件离线验收发现过一个真实问题：导出完成后进入题目详情，多次渲染触发同一个笔记宿主的并行异步绑定。旧数据库读取返回时，原实现会新建并替换缓存草稿，同时把输入框恢复为旧值。用户刚输入的文字仍在旧事件闭包里，却已经脱离统一草稿表，导致随后切页刷新与紧急备份看不到修改。

修复后，同一 DOM 宿主只绑定一次并共享尚未完成的绑定 Promise；每个题目身份共享加载 Promise。token 和 generation 阻止脱离 DOM 或数据恢复前的旧任务重绘；数据库读取完成后重新检查当前草稿、dirty 和编辑序号，始终原地维护事件闭包使用的同一草稿对象。普通切页准备不再提前移除仍可能接收输入的干净草稿。`flushLearning53()` 循环等待真正提交，并继续排空提交期间新输入的文字，不能在有更新输入时提前返回“已保存”。

`tests/learning-note-race53.test.mjs` 使用真实学习接口和受控延迟，精确覆盖三种顺序：重复绑定后立即输入并切页；数据恢复前旧读取迟到；前一事务提交期间继续输入。三个新增回归与学习、答题和既有性能回归合计 **30/30 通过**，日志 `docs/LEARNING_53_RACE_TESTS.txt`。实际单文件离线浏览器脚本由主代理在最终打包后复验，不以 Node 宿主替身代替浏览器结果。便携版导出后的测试须先关闭下载对话框，再编辑题目笔记；模态框开启时背景输入区不可交互，不能用无效输入判断笔记保存。

`protectedQuestionIds53()` 从未交卷组取得永久身份，旧概要缺少身份列表时采用保守的 `*` 标记；`isQuestionProtected53()` 再检查真实持久草稿。详情、个人笔记、搜索结果、题目编辑和导入/导出管理入口都会避免暴露当前题组的答案。历史组只要有一题与未交卷组重叠，整组历史选择、答案、解析和笔记均暂时隐藏。不同窗口通过 BroadcastChannel 通知草稿状态，已打开笔记也会按新的保护状态收起。这是产品界面防提前展示机制，完整用户备份仍按原协议保留全部数据。

## 图形题库管理与更新

保留官方题库、自建展示题库和来源包目录。支持按题库名称/分组、科目筛选，按题干/选项/解析/分类/标签查询，按精确分类筛选，最多显示一页 30 题。新增、编辑、删除均调用既有逐题接口；新增只写本地数据库，不要求先创建 JSON。

现有验证器增加可选 `category` 文本与最多 30 个不重复 `tags`；旧题没有这些字段仍有效。题目变化不覆盖个人笔记，不重算历史得分。

普通 JSON 导入和补丁继续先预检并确认；有本地冲突时显示本地与导入内容，可保留本地并取消，或明确选择采用导入。后者调用原 `prepareResourceImport(..., {resolveLocalConflicts:'incoming'})`，把问题内容变化与对应本地来源标记移除放在同一个事务，写入失败时完整回滚，没有“先逐题删除本地覆盖、随后导入失败”的中间状态。

## 概要、历史与统计

`settings:learning-overview53` 在交卷事务中更新，包含 `schemaVersion`、`weekStart`、`weekAnswers`、`pendingWrong`、`recent`、`lastBankId`、`updatedAt`。其中 recent 是摘要，没有题目和答案快照。老数据缺少本记录时，首页不为此扫描所有历史；后续掌握/收藏操作或交卷可补齐。

历史页明确进入后才读取历史，按 30 组分页展示；查看记录复用既有快照。统计按最近 7 天、30 天或全部时间计算：练习组数、作答题次、按源身份去重的不同题目数、总体正确率、分来源题库与分类表现。待复习和星标收藏是当前状态，不受历史时间过滤影响。未交卷题组不进入这些统计。

当前历史统计在显式页面中读取历史快照，未额外维护第二份完整统计数据库；长期累计非常多的历史时，可在真实测量后增加摘要索引。关键词查询仍使用既有分批扫描，不引入全文引擎。

## 保存与备份验证

`validateQuizRecords` 同时校验新增收藏夹结构及学习标记可选字段。完整 JSON 已经包含 `learning:*`、`question:note:*`、`quiz:*` 普通用户键，沿用现有备份校验与原子恢复。收藏夹允许保留已经删除题目的身份，避免导入或删除题目时损坏已有整理关系。

本轮 Node 执行：

```text
node --experimental-vm-modules --test tests/quiz.test.mjs tests/performance50.test.mjs tests/resources.test.mjs tests/learning53.test.mjs
```

40 项通过，无跳过。其中 5 项新增端到端业务逻辑测试覆盖分类/标签、冲突采用导入及注入失败回滚、交卷前详情/搜索/笔记保护、错题时间与掌握状态、收藏夹多对多与备份恢复、统计去重和时间范围。旧历史测试已加强为重叠整组隐藏，未放宽答案保护。

实际 Edge 测试脚本为 `tests/learning53-browser.mjs`，原始证据位于 `docs/evidence53/learning53/evidence.json`。由主代理执行并汇总最终结果；新增第八项专门注入笔记配额失败，验证紧急完整备份仍包含未提交笔记。移动尺寸是 Windows Edge 的视口仿真，不等同 Android Edge 真机。
