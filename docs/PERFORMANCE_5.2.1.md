# 5.2.1 性能对照实测

环境：Windows，实际 Edge 156.0.4314.42，无头模式，1440×1000。每版各 3 个全新浏览器上下文；同一台设备、同一脚本、同一生成算法。测试通过本地 HTTP 运行，关闭 Service Worker 以分离程序与网络缓存影响；PWA 缓存另有实际离线测试。下表除字节外时间单位均为 ms，采用中位数。

压力数据：5000 道稳定 ID 单选题，40 条 256×256 图片记录（复制同一确定性伪随机 PNG，考察附件数量和数据库写入）；自动保存测量实际文本编辑到事务完成。冷启动为空库；热启动为同上下文已有压力数据后的 reload，未声称是真机安装外壳启动。启动数据不含自动离线预缓存流量。图片列表测量显式开启所有 40 个 img 的 eager 加载并等待 decode()，公平比较整份列表解码，避免把新版屏外 lazy 图片尚未请求误当成已预览完成。最终新旧性能脚本单独执行，未并行打包或跑单元测试。

结果与取舍：首屏减少字体、地图和导出依赖的读取；普通编辑保存只比较和更新发生变化的记录。第一次保存图片需要解码并生成缩略图，第一次导入逐题记录需要更多 IndexedDB 请求，因此二者比旧版整包写入更慢。这是本次实测暴露的明确成本，没有把它们描述为性能提升。对 5000 题的后续修改只写变化的题目；随机练习按数量读取题目，不加载全库。

内存为浏览器 performance.memory 的采样估算，受 GC、共享字符串和进程调度影响，不能当成稳定的物理内存占用或内存改善结论。此次连续切换后数值接近，甚至可能高于旧版；不承诺内存下降。初次图片预览单独的原件/缩略图验证见 storage521 实际浏览器证据，不将一次采样外推成普遍加速。

复跑：在工程目录运行 `node tests/performance521-browser.mjs ../qicheng-5.2` 与 `node tests/performance521-browser.mjs .`。浏览器路径见脚本，可按本机安装调整。两份 `PERFORMANCE_*_RAW.json` 保留逐轮原始数据。此处不包含 Android Edge 真机或真实设备存储压力驱逐测试。
