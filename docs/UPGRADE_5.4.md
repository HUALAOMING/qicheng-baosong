# 5.4.0 升级与数据迁移

## 日常保存

菜单和编辑区的“保存进度”、Ctrl / ⌘ + S 将当前工作资料写入本机 IndexedDB，不生成文件。输入仅标记未保存，不再在 500ms 后、焦点移出或内部导航时序列化与保存整个工作区。资料保留在内存中直到保存；离开页面有未保存修改时会显示浏览器提示。浏览器强制结束无法保证出现提示，请完成编辑后保存。答题、阅读等独立记录保持各自提交/暂存逻辑，安全更新前仍提交当前工作进度。

现有存储已按记录增量写入并将原图/附件存为 Blob，因此继续使用，不改换数据库、不额外复制原件。学习数据导出先按键筛选，避免读取附件 Blob；资料导出只有结构化文字和引用，原件仅在明确导出附件时读取。

依据：[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)、[MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)。IndexedDB 支持异步存储结构化对象与 Blob；移动设备退出事件不可靠，因此不把退出时写入当作唯一保存保障。

## 备份和恢复

设置有独立的“导入与导出”页面，三个选项默认不勾选。个人资料与简历为 JSON；学习中心（含自我介绍和阅读草稿）为 JSON；附件/照片/上传最终简历以 ZIP 保存原始文件和校验清单。简历背景图按内容去重后随附件包保存，不在资料 JSON 内重复编码。多模块下载保留独立文件，装入一个外层 ZIP，便于一起传输。文件中心也可仅选择文件夹或具体文件导出。

分别的上传入口可导入对应文件，也可通过批量入口一次上传多个文件或外层 ZIP。个人资料中真正引用的原件必须已在本机或一起提供，缺失时中止并说明。学习模块按编号合并，同编号更新，其他记录保留；旧版完整 JSON 保留完整恢复行为并明确提示替换。

输入文件先通过格式、SHA-256、路径和引用检查，再计划导入并确认。资料、附件、题库写入一次 IndexedDB 事务；磁盘写入失败则回滚。规划期间有其他窗口修改时通过全库修订号拒绝覆盖。相同附件编号而原文不同会拒绝导入。

## 迁移与回退

继续使用 `qicheng-v4` 数据库、数据库版本 2 和工作区格式 6。不清空或重新建立用户数据库。旧数据新增空文件夹、仅展示成绩集合与草稿；保留旧字段、图片/文件编号、简历内容、学习资源与独立记录。旧数据只有在显式保存时才提交正常增量写入。

原站点采用现有安全 PWA 更新协议。新资源必须全部校验成功，更新前提交资料，多窗口协调后再切换；下载中断或资源不一致时旧版仍可使用。建议由应用“保存并更新”入口应用新版；不要清除浏览器站点数据。回退程序代码前应导出最新分模块备份，以免旧程序不认识新功能字段。

## 验证范围

真实 Windows Edge 的独立测试配置验证旧 5.3.2 到新版的同地址升级、旧完整 JSON 恢复、原件字节一致、输入零工作区写入、手动保存重载、文件夹与成稿、分模块恢复、克隆和成绩分离。桌面/平板/手机尺寸采用视口模拟，不等同于实体 iPad/Safari 实测。测试仅用合成资料，不读取现有用户浏览器配置。
