## 数据层约定

保持原生 ES modules 与 HTML/CSS，不更换框架。UI 通过统一 storage API 与业务模块访问数据。`@521:` 为内部数据命名空间，不写入外部备份；旧逻辑通过稳定的投影 API 兼容。外部输入不接受本机 Blob 指针。应用版本 5.2.1、IndexedDB 结构版本 2、内部工作台模型版本 1、原有公开草稿版本 6 和备份协议版本 2 分别管理。

- 个人资料、经历、荣誉、院校收藏、文档版本按字段/ID 存储；有序集合的顺序保存在关联清单。
- 题库头部含永久 ID 及有序题目 ID；每题一行，主键前缀用 IndexedDB 有序键索引查询。有限练习按请求数量读取，不一次渲染几千题。
- 答题历史保留作答时的问题与答案快照；新题库的改答案、删除不会回算旧分数或删除学习标记。
- 首页概要是可重建派生数据，权威记录仍为原始学习行。完整导出读取权威数据。
- 不采用 ORM，不依赖普通 HTTP 缓存保存资料。新增业务键须定义稳定 ID、校验、事务和备份投影，并补错误与并发测试。

## 存储技术与持久授权

IndexedDB 同时承担结构化资料与 Blob 附件，便于原子恢复和统一备份。OPFS 仍受同一浏览器 origin 配额与站点管理；本次没有证明它相对 Blob 的收益，不增加第二套文件生命周期。Cache Storage 仅存程序资源，不存个人资料。LocalStorage 不承担用户数据权威存储；更新过程短暂使用 sessionStorage 保存待验证的版本号。

首次点击继续时检查 persisted() 并在未授权时尝试 persist()；设置可手动申请或重查。所有模式均由实际返回值决定，失败可继续编辑。estimate() 只标注为站点用量/配额估算；不代表设备准确剩余空间。Windows 的 showSaveFilePicker 由用户点击后选位置，完成 writer.close 才记录写入成功；不支持时保留标准下载/导入，并把“已生成”和“已确认文件留存”分开。

持久存储降低自动驱逐风险，不能抵御主动清除站点数据、配置文件清理、卸载或硬件故障；普通程序缓存清理与清除全部站点数据在设置中分开说明。授权不能代替外部备份，也不承诺会出现系统权限弹窗。

研究依据：[Chrome 团队的持久存储说明](https://web.dev/articles/persistent-storage)、[StorageManager.persist](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/persist)、[estimate](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/estimate)、[OPFS 的站点边界](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system)。Chromium 的自动判断不能当成 Android Edge 每一版本/设备的授权保证，本工程用能力检测处理。

## 统一任务与备份协议

tasks.js 的每项任务具有名字、阶段、已处理/总数、终态与摘要；渲染通过 animation frame 合并更新。不用计时器增长百分比，阶段已处理全部项目而事务尚未提交时仍显示等待；失败为终态。JSON 读取与工作线程解析、题库验证及增量提交、完整备份校验/恢复、批量附件、导出排版与 PWA 资源安装共用这一组件。JSON 工作线程不可用的独立 HTML 在主线程回退，不假称完全无阻塞。

完整备份为标准 UTF-8 JSON，附件用原质量 Base64，故大备份会占用额外内存；没有为了形式采用 ZIP。SHA-256 用于发现意外改动，不是身份签名，也不是加密。未带哈希的旧 v1 文件只能做结构与引用校验；恢复仍需用户确认。导出可在本地保存失败时尽量救出当前内存内容，但会明确说明数据库异常；不会把文件生成当成文件落盘证明。

## 已知限制与后续约定

- Windows Edge 的实际浏览器测试和移动视口仿真不等于 Android Edge 真机或操作系统 PWA 外壳验证。持久授权受浏览器策略影响，真实磁盘满、浏览器自动驱逐和系统卸载不能用注入异常代替。
- 当前以保守冲突拒绝保护多标签页，需用户另存当前编辑并重新载入；不做自动多端合并、云同步或后台独立磁盘写入。
- 全库导入首次拆行、原图缩略图生成比旧整包写入慢；日常增量变更受益。完整 JSON 和可编辑 HTML 导出仍有峰值内存成本；详见性能实测与原始记录。
- 为保持原功能，部分 UI/业务模块仍静态依赖 app.js；大依赖和数据已按需，未声称整个旧代码库均动态分块。后续新模块应避免再扩大环形依赖。
- 缓存哈希是程序内容契约；修改运行时必须重新 package，再 check 与测试。不得手改生成 worker 的资源列表。
- 稳定题目 ID 不能随排序或解析修订改变；禁止通过补丁隐式覆盖未指定字段。改答案与删除必须保留历史。

测试汇总与性能结果分别见 TEST_REPORT.md 和 PERFORMANCE_5.2.1.md；各专项文档及原始证据随工程交付。
