# 5.3.0 后续维护约定

1. 使用现有 storage 事务及修订检查，工作区写入由统一 autosave 承担。不建立第二套数据库、localStorage 正文副本或另一套保存时钟。跨窗口冲突明确拒绝，不能通过重新读取 revision 重试覆盖。
2. 简历操作明确 version ID，以 Object.hasOwn(overrides,path) 识别覆盖；空字符串不是未覆盖。预览/导出使用 resolveResume53。删除底稿条目前 preserveResumeReferences53，清理原件前检查版本引用。
3. 迁移保持幂等、不伪造修改时间；同步更新校验、备份和独立 HTML。撤销栈只保存当前会话，不能把大附件放入快照。
4. 题目身份采用来源题包 ID + 题目 ID，展示题库仅是分组。复用逐题 CRUD/queryQuestions/saveQuestionNote；笔记不混入标准解析，历史保留评分与原题快照。
5. 离开页面、备份、导出和更新必须等待已接受写入。失败保留内存草稿并允许救援备份。新学习入口必须接入未交卷保护，包含旧历史和搜索。
6. 新的大页面通过 features53 按需导入，首页只读概要，文档生成库按需加载。预缓存下载与页面初始化应分别测量。
7. 原图/文件保持 Blob 原文，不生成缩略图，素材列表只读取元数据；打开原件或生成相关导出时才读取二进制。
8. 所有模板 DOCX 保留原生文字、可调整图片和自然分页；不生成整页图片或编辑保护。检查长段落、封面、目录、双栏及旧导出格式。
9. 新模块/导出名称同步 scripts/package.mjs 拼接顺序与 portable registry，必须验收独立 HTML，不能仅测 PWA。
10. 发布前运行 package/check/Node 和受影响浏览器专项；保留原始测量。视口模拟不写成真机测试，XML 检查不写成 Word 打开验证。push、Release、Pages 需用户另行明确授权。

优先处理真实瓶颈。历史累计很大时再增加摘要索引；当前分批扫描可用时不引入全文引擎。存储调整先验证迁移、回滚、并发与备份，保留升级前外部备份。
